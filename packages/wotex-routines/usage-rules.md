# Wotex Routines usage rules

These rules describe the completed public target contract. The package
catalogue records implementation status separately.

- Supply explicit limits and an immutable offline installed contract closure.
  Basis data may select installed meanings; it cannot install implementations,
  choose credentials, authorize an interaction or qualify a device.
- Use documented constructors and checked projections. Match payload-free
  errors by code/path. Do not treat caller-built structs as already validated.
- Preserve dimensions, exact units, source/receipt epochs, sequence, freshness,
  replay, continuity and derivation. Unknown is distinct from false or zero.
- Convert scalar values only to exact in-domain integers. Receipt precision is
  separate: explicitly install the exact clock or conservative floor-millisecond
  clock; never pair an old report with current processing time.
- Install the entire `InputMapping` identity before joining a Profiles proposal.
  Supply both limit selections and an explicit qualified clock correspondence;
  retain proposal/mapping/correspondence witnesses and recheck consumer admission.
  Unsupported quantities/shapes cannot relabel a legacy dimension or add an operator.
- Use `Input.binding_basis/3` for external Snapshot/Edge bindings, retaining the
  complete installed Mapping and external profile identity. Preserve explicit
  null receipt UTC and exclusive expiry; neither a Basis digest nor an evaluation
  timestamp can replace them.
- Use the public Continuum adapter with explicit scope and evidence references.
  Missing source time refuses conversion; receipt time cannot replace it.
- Whole-resource effect domains remain conservative. A protocol response is
  not reported equality or physical cause; uncertain absolute operations are
  governed by the installed repeat contract.
- Use civil queries for explicit finite weekday/time spans. Supply every policy
  and an immutable database; points have no DTSTART ordinal or continuation.
  Preserve original coordinates and database basis, regenerate checked pages,
  and reproject after clock-generation changes. Output overflow refuses the
  whole result. Missing producer capability never falls back to availability.
- Kernel proposals and analysis are inert. The consumer owns collection,
  admission, durable originals, policy, clocks, supervision and effects.
- The normative specifications define the entire accepted programme; the
  catalogue separately records the implemented subset and executed evidence.
