# External profile-reader completion contract

Version: 0.2.2. Updated: 2026-10-13. Status: accepted target.
Implementation: partial reader. Evidence: focused reader/structural-schema suites.

This optional producer reads consumer-owned device/semantic definitions.
It ships no world's-sensors catalogue or vendor-model selection authority.
The independent optional package is registered. WPF.01 reader constructors,
limits, numeric admission, offline schemas and independent identity fixtures
are implemented. Exact bounded Unit.convert/4 is implemented; compiler,
report interpretation and authoring remain planned.
Two isolated reader consumers passed against exact archives; full compiler,
interpretation and authoring acceptance remains open. See
[reader evidence](../provenance/reader-2026-10.md).

1. Freeze WPF.01 profile/definition/registration schemas, limits and canonical
   vectors. Show an unseen quantity without adding a reader enum.
2. Register an independent optional package when implementation begins; prove
   passive loading and public core/Runtime API closure.
3. Implement WPF.02 compile/interpret/unit algebra against independent schemas,
   rational math and C02 vectors; no I/O in constructors/compiler/interpreter.
4. Implement WPF.03 contract export, local-reference finalizer, structured
   diagnostics and CLI adapter through that same checker. Freeze declared
   draft-07 dialect/rules and provider-independent parity/refusal vectors.
5. Exercise consumer-owned industrial multi-channel and second independent consumers
   against archives; compare raw decoding, null/quality/time and projection.
6. Prove manual/offline authoring, consumer-private draft/source custody and
   current-basis admission. Optional AI drafting follows that working path;
   unavailable providers and wrong-but-schema-valid mappings refuse honestly.
7. Implement WRO.05 explicitly qualified joins; retain unsupported v1 routine
   dimensions/shapes honestly. Reader use never depends on the routine engine.
8. Run focused mechanism tests and changed-package milestones; actual device,
   publisher/update custody and consumer authority gates are separate.

The owning [WPF.01](../specs/WPF.01-external-profile-language.md) and
[WPF.02](../specs/WPF.02-profile-interpretation.md) and
[WPF.03](../specs/WPF.03-profile-authoring-contract.md) define fields/defaults/errors,
rather than leaving them to a implementation convention. Broader binary-float,
nonlinear math or schema operators need a new explicit projection contract.
Consumer templates release and qualify independently of this reader. No new
definitions repository or provider dependency is required. The
[research decision](https://github.com/wotex-project/wotex/blob/main/docs/architecture/consumer-profile-authoring-research.md)
records primary evidence and rejected alternatives.
