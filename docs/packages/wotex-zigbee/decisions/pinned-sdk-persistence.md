# Pinned SDK persistence review

Host source baseline: `e83639c87e91653a0c611a668156cfa4533377b8`, package `packages/wotex-zigbee`.
Reviewed backend: TI CC26x2 SDK 2.30.00.34, SWRA198 revision 1.14.

The current host keeps raw NV reads/writes, coordinator address mutation and
reset outside ordinary command admission. This review retains that boundary.
The reviewed commands do not establish a complete safe backup/restore procedure;
no export/import API, packed NV image or counter-continuity claim is adopted.
WZG2-02 and WZG2-T4 remain open.

## Exact inputs

The [machine-readable source review](../../../../packages/wotex-zigbee/test/support/profiles/znp-persistence-review-mt-r1.14.json)
pins the SDK installer, bundled Monitor/Test PDF and seven reviewed source files
by full SHA-256 digest. The installer was extracted without executing it.
The source review is distinct from installed-firmware execution and physical
qualification. A `SYS_VERSION` tuple does not identify the binary or build flags.

## Persistence and counters

`ZDApp_SaveNwkKey` reads the active key/counter into a C struct, writes its NV
item, then separately updates the matching network-security-material entry.
The fallback uses a generic entry. These separate writes do not constitute an
atomic image, and the shown routine does not check each NV call's result.
`ZDApp_NVUpdate` may schedule a delayed save for a coordinator. A coherent
metadata observation and a successful NV read therefore do not establish that
the stored counter matches current radio use or that every item belongs to one
snapshot.

`ZDApp_RestoreNwkSecMaterial` selects network-specific or generic counter
material and adds `MAX_NWK_FRAMECOUNTER_CHANGES` plus
`NWK_FRAMECOUNTER_CHANGES_RESTORE_DELTA` once per reset. The reviewed header's
1000 and 250 defaults are build-overridable. The source adds into a uint32
counter without an explicit overflow refusal in that routine. It does not
compare the value with an independent durable high-water record or prove
that another coordinator has stopped using the same identity and key.
A restart increment is consequently insufficient evidence for restoring an
old backup. Host code must not assume that adding the source default makes
an arbitrary image fresh.

`ssp.h` declares active sequence, key and counter fields. These declarations
do not specify the exact installed compiler's struct offsets, complete NV
inventory, Trust Center/link-key state or a portable snapshot format. A
payload cannot be copied between builds or chipsets on that basis.

## MT access and mutation

Legacy and extended-offset NV reads call `MT_CheckNvId`. Its certificate/key
checks depend on build flags. In the reviewed extended-ID `MT_SysNvRead`, the
access-check result is assigned before an unconditional `nvFps.readItem` call
reassigns `error`. That source arrangement cannot be cited as proof that the
installed extended-ID command denies private reads. This is a source observation,
not a reproduced installed-firmware security result.

NV writes update individual items; writes at offset zero can update in-memory
Z-Globals. Writing the extended-address item also changes the MAC address.
An SRSP status is an individual operation result, not an atomic restore,
coordinator-isolation receipt or proof of counter continuity. Raw commands
therefore remain unavailable through the finite ordinary host API.

## Executable refusal evidence and remaining implementation

[backup_boundary_test.exs](../../../../packages/wotex-zigbee/test/wotex/zigbee/backup_boundary_test.exs)
checks independently framed, source-pinned NV/identity command layouts and
receiver refusal before I/O. Transient write tests use runtime-generated bytes;
no key fixture is stored. They check private-material exclusion from errors,
owner state/dictionary and queued events, then execute a normal query to verify
that refusal leaves the owner usable. They do not implement or validate a
backup, stale-image watermark, isolation receipt or successful restore.

A supported restore backend still needs an exact firmware/build and complete
private inventory, a qualified quiesce/export/import sequence, durable snapshot
and high-water custody, counter-overflow refusal, old-coordinator isolation,
crash/partial-write behavior and independent physical continuity evidence.
Its own procedure must also establish secure joining/fallback policy. Missing
continuity requires refusal and a separately authorized recovery procedure;
raw NV access is not that recovery procedure.
