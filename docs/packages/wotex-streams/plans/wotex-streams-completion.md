# Protocol-stream completion contract

Version: 0.1.0. Updated: 2026-10-13. Status: accepted target.
Implementation: planned. Evidence: missing.

The optional prospective producer supplies neutral stream delivery values/ports,
not a complete audio/video/sensor-processing platform. Its documentation tree
does not register a source package or generated family entry.

1. Freeze WST.01 descriptor/frame/status/control/port schemas and independent
   lifecycle/credit/original vectors. No implicit codec, clock trust or native IPC.
2. Register an independent optional package at explicit implementation entry;
   exercise public ports and application-free loading against archives.
3. Select one exact WST.02 protocol/role/format cohort and write its concrete
   wire/security/state/parameter contract and independent peer vectors before code.
4. Prove independent packet/session/guard/cancellation/cleanup behavior, with
   protocol timing and delivery distinct from consumer processing/render evidence.
5. Exercise a second independent stream consumer/profile, including one media
   use and another distinct deployment or format. Consumer policies/custody stay
   separate; no worldwide camera/speaker definitions ship with the library.
6. Adopt further protocol profiles only through their own source/dependency/notice
   and conformance gates. Surveillance starts from actual ONVIF/RTSP/RTP assessment;
   WebRTC and Sendspin are separately negotiated, never aliases.
7. Run focused mechanism checks and changed-package/native milestones; physical
   output, signed capture, recording and analysis gates stay with their consumers.

The owners are [WST.01](../specs/WST.01-stream-values-and-lifecycle.md) and
[WST.02](../specs/WST.02-protocol-profile-allocation.md).
Exact library/SDK choices remain per-profile entry artifacts. Core/Runtime need
no mandatory FFmpeg, GStreamer, Core Audio, playback or surveillance engine.
